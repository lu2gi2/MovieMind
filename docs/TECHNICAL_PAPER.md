## What We're Building

A movie recommendation system where **movies, users, and moods all live in the same mathematical space.** Recommendations are generated by taking the user's position in this space, nudging it in the direction of their current mood, and finding the nearest movies.

### The Core Equation

```
recommendation = nearest_movies( user_position + (λ × mood_direction) )
```

That's it. One equation. Three components. No separate models glued together.

### What Makes It Different

| Normal Recommender | Our System |
|-------------------|------------|
| "You like Thrillers. Here's another Thriller." | "Your taste lives in the 'smart heist film' neighborhood. We nudged you slightly toward 'more excitement.' Here's what's nearby." |
| Mood = filter by genre | Mood = direction to walk in |
| User = list of genre preferences | User = a precise point in the same space as movies |
| Recommendations are categorized | Recommendations are discovered by proximity |

## The Problem With Normal Recommenders

### Problem 1: Genre Labels Are Meaningless for Recommendation

A genre is a marketing category, not a description of what a movie *feels like.*

| Movie | Genre Tag | What It Actually Is |
|-------|-----------|-------------------|
| *Ocean's Eleven* | Thriller | Witty heist ensemble with comedic timing |
| *Hereditary* | Thriller | Slow-burn occult horror about family trauma |
| *Gone Girl* | Thriller | Twisty domestic psychological drama |
| *Sicario* | Thriller | Gritty, tense drug-war procedural |

Four movies. One genre. Zero overlap in what the viewer experiences. A genre-based recommender treats them as interchangeable.

**What we do instead:** Each movie gets a 384-dimensional vector where position represents its *actual vibe* — pacing, tone, themes, emotional register, narrative structure. *Ocean's Eleven* and *The Italian Job* end up neighbors. *Hereditary* is on the other side of the map.

### Problem 2: Mood and Taste Are Disconnected

Every existing mood-based recommender works like this:

```
User selects "Excited"
  → System: "Excited = Action + Adventure genres"
  → System: Boosts movies with those genre tags
  → System: Ignores everything it knew about the user's taste
```

The mood system and the taste system don't communicate. A user who only watches slow-burn dramas but selects "Excited" gets *Fast & Furious* — which they'll hate. The system threw away its user model at the moment it mattered most.

**What we do instead:** Mood doesn't replace taste. Mood *nudges* taste. The user's position shifts slightly toward excitement, but stays in the same general neighborhood — close to the kind of movies they actually like.

### Problem 3: TF-IDF Doesn't Understand Language

Most content-based recommenders (including our current system) use TF-IDF: count how often words appear, weigh rare words higher. This has fundamental limitations:

```
TF-IDF comparison:
  "bank heist" vs "robbery"          → similarity: 0.00 (zero word overlap)
  "mind-bending" vs "cerebral"      → similarity: 0.00 (zero word overlap)
  "tense thriller" vs "suspenseful" → similarity: 0.00 (zero word overlap)
```

The system cannot connect synonyms, related concepts, or thematic patterns. It only matches exact words.

**What we do instead:** Sentence Transformers encode *meaning*, not words. "Bank heist" and "robbery" are close because the model understands they refer to the same concept. "Cerebral" and "mind-bending" are close. The embedding captures what words *mean*, not what they *are.*

### Problem 4: No Gradual Control Over Mood Influence

Normal systems: mood is either ON or OFF. There's no "a little bit excited" vs. "extremely excited."

**What we do instead:** The λ (lambda) parameter provides continuous control:

```
λ = 0.0: Pure taste. "Show me exactly what I usually like."
λ = 0.3: Light mood influence. "My taste, but make it a bit more exciting." (DEFAULT)
λ = 0.7: Strong mood influence. "Push me way out of my comfort zone."
λ = 1.0: Pure mood. "Ignore my history, just give me the most exciting films."
```

The user gets a slider. The system gets a tunable parameter for evaluation.

## How Our System Works

### Step 1: Encode Every Movie Into a "Vibe Vector"

We take each movie's rich metadata — plot summary, tagline, genres, keywords, director name, top cast — and feed it into a Sentence Transformer model.

```
INPUT: "Two rival magicians in Victorian London engage in a bitter feud 
        to create the ultimate illusion, sacrificing everything in an 
        obsessive quest for supremacy. Mystery Thriller Drama Mystery 
        Thriller Drama Christopher Nolan Hugh Jackman Christian Bale 
        magic rivalry obsession twist dual-identity sacrifice"

MODEL: all-MiniLM-L6-v2 (Sentence Transformer)

OUTPUT: [0.23, -0.45, 0.78, 0.12, -0.33, 0.56, -0.19, 0.41, ...]
        ↑ 384 floating-point numbers that encode the movie's 
          "position in semantic space"
```

**Why 384 dimensions?** `all-MiniLM-L6-v2` produces 384-dimensional embeddings. This is the standard size for this model class — large enough to capture rich semantic relationships, small enough to be fast and memory-efficient.

**What these numbers represent:** Each dimension corresponds to some latent semantic feature learned during the model's training. Dimension 12 might loosely correspond to "pacing," dimension 87 to "emotional intensity," dimension 201 to "narrative complexity." We don't label these dimensions — we don't need to. The math works regardless.

**Storage:** 5,000 movies × 384 floats × 4 bytes = ~7.7 MB. Stored as `movie_embeddings.npy`.

### Step 2: Build User Taste as a Centroid

Every time a user likes a movie, we pull that movie's vibe vector and blend it into the user's taste centroid:

```
INITIAL: User has no taste vector (empty)

LIKE "Inception"      → taste = inception_vec
LIKE "The Prestige"   → taste = (inception_vec + prestige_vec) / 2
LIKE "Ocean's Eleven" → taste = (inception_vec + prestige_vec + oceans_vec) / 3
LIKE "Heat"          → taste = (inception_vec + prestige_vec + oceans_vec + heat_vec) / 4

...and so on.
```

The taste vector is literally the **center of mass** of all the movies the user has liked. It drifts over time as the user likes more movies, gradually converging on their true preference region.

**Storage:** 384 floats stored as JSON in the `users.taste_vector` column. Same database column as current, just different content.

**Unlike handling:** When a user unlikes a movie, we recompute the centroid from scratch (excluding the unliked movie) rather than trying to "subtract" it. This is more accurate than negative blending.

### Step 3: Learn Mood Direction Vectors

For each of the 10 moods in our system (happy, sad, excited, relaxed, romantic, thrilled, nostalgic, adventurous, thoughtful, scared), we compute a direction vector.

**Method: Mean Difference**

```
For mood "excited":

1. Identify excitement-exemplar movies:
   Movies associated with high-energy, fast-paced, high-stakes experiences.
   Selected via keywords: "fast-paced", "action-packed", "thrilling", 
   "high-stakes", "adrenaline", "intense", "relentless"
   
   Examples: "Mad Max: Fury Road", "Baby Driver", "Edge of Tomorrow",
             "Mission: Impossible - Fallout", "John Wick", "The Raid",
             "Speed", "Die Hard", "Crank", "Dredd"

2. Compute their average position in embedding space:
   excited_center = mean(embeddings of excitement-exemplar movies)

3. Compute the average position of ALL movies:
   global_center = mean(embeddings of all movies)

4. The mood direction = the arrow pointing from global center to excitement center:
   excited_direction = excited_center - global_center
   
5. Normalize to unit length:
   excited_direction = excited_direction / ||excited_direction||
```

**What this means:** The mood vector literally "points" from the average movie toward the region of the embedding space where exciting movies cluster. It's a compass pointing toward excitement.

**Why this works:** The embedding space is linear (cosine similarity is the distance metric). Vector addition is meaningful. Moving a point in the direction of a mood genuinely shifts it toward movies with that mood quality.

**Storage:** 10 moods × 384 floats = 15 KB. Stored as `mood_vectors.npy`.

### Step 4: Generate Recommendations via Mood-Shifted Search

This is the core algorithm. Given a user, an optional mood, and a λ value:

```
Algorithm: MoodShiftedRecommend

Input:  user_taste_vector (384-dim)
        mood_direction    (384-dim, optional)
        lambda λ          (float, 0.0 to 1.0)
        k                 (int, number of recommendations)

Output: top_k_movies

1. If mood is provided and λ > 0:
      search_position = user_taste_vector + (λ × mood_direction)
   Else:
      search_position = user_taste_vector

2. Compute cosine similarity between search_position and every movie embedding:
      similarities[i] = cosine_similarity(search_position, movie_embeddings[i])

3. Filter out already-liked movies

4. Sort by similarity (descending)

5. Apply diversity filter:
      max_per_vibe_region = max(2, k / 3)
      (ensures recommendations aren't all from the same narrow cluster)

6. Return top k results with similarity scores
```

**Time complexity:** O(n) per query for n movies. For 5,000 movies × 384 dims, cosine similarity computation takes ~2 milliseconds on CPU. This is fast enough for real-time use without caching.

### Step 5: Generate Explanations

Since user position, mood direction, and movie positions are all in the same space, we can compute geometric explanations:

```
For each recommended movie m:
  1. contribution_taste = cosine_similarity(user_taste, m)
     "How much of this recommendation comes from your taste?"

  2. contribution_mood = cosine_similarity(user_taste + λ × mood, m) - contribution_taste
     "How much did the mood shift improve this match?"

  3. nearest_liked = argmax(cosine_similarity(m, liked_movie) for liked_movie in liked_movies)
     "Which movie you liked is this most similar to?"
```

This enables explanations like:
- *"85% taste match. Reminds us of Inception (which you liked). 15% boost from your Excited mood."*
- *"This is close to The Prestige in pacing and structure, nudged toward higher energy."*

No existing system can do this because their models live in separate spaces.

## Advantages Over Existing Systems

### 1. Semantic Understanding Beyond Keywords

| Query Concept | TF-IDF Result | Our System Result |
|--------------|---------------|-------------------|
| "heist film" | Matches movies with the word "heist" | Matches "robbery", "bank job", "con artist", "caper" films |
| "mind-bending" | Matches movies with the word "mind-bending" | Matches "cerebral", "psychological", "surreal", "twist ending" films |
| "slow burn" | Matches movies with "slow" and "burn" | Matches atmospheric, methodically-paced films regardless of keywords |

### 2. Mood That Respects User Identity

```
Scenario: User only likes romantic comedies. Selects "Scared" mood.

Genre-based recommender:
  "Scared" → Horror + Thriller genres → Shows "The Conjuring"
  Result: User is terrified (and not in the way they wanted)

Our system:
  User centroid is in the rom-com region
  "Scared" direction shifts slightly toward spooky
  → Shows "Clue" (comedy mystery), "Happy Death Day" (horror comedy),
    "Zombieland" (comedy horror)
  Result: Movies that are spooky but still comedic — respecting the user's core taste
```

### 3. Controllable Mood Intensity

No system allows users (or the system itself) to control *how much* mood influences results.

```
λ = 0.0: "I just want more of what I like. Ignore my mood."
λ = 0.3: "I'm feeling a bit adventurous. Nudge me gently."  ← DEFAULT
λ = 0.7: "I want something different today. Push me."
λ = 1.0: "I don't care about my history. Just go by mood."
```

This is both a user-facing feature (a slider in the UI) and a research parameter (we can evaluate at every λ value).

### 4. Explainable by Geometry

Because everything lives in the same space, explanations aren't random templates — they're computed from actual vector relationships:

```python
# How much did the mood shift help this recommendation?
mood_contribution = cosine_sim(taste + λ × mood, movie) - cosine_sim(taste, movie)

# Which liked movie is this closest to?
nearest_liked = max(liked_movies, key=lambda m: cosine_sim(m.embedding, movie.embedding))
```

The explanation system can say things like:
- *"This is 92% similar to Inception (your taste) with an 8% boost from your Excited mood."*
- *"The mood shift moved this recommendation from #15 to #2 in your ranking."*

### 5. Cold-Start Friendly

New user with no history? Their taste centroid defaults to the global average movie position. The first few likes rapidly pull the centroid toward their true preference region. The mood system still works because mood directions are pre-computed from the full dataset.

### 6. Single Unified Space

No separate content model + emotion model + genre model + collaborative model. One space. One similarity function. One equation. This means:
- **Simpler code:** One recommendation path, not four scoring branches
- **Easier debugging:** Everything is a vector. Every decision is a distance computation.
- **Natural extensibility:** Want to add "time of day" or "weather" as context? Add another direction vector.

## Why This Is Paper-Worthy

### The Research Gap

We searched the literature on affective recommender systems (including the comprehensive 2025 survey, arXiv:2508.20289). The survey explicitly identifies these as **open problems:**

1. > *"No unified framework encodes mood and content in the same latent space."*

2. > *"Existing work treats affective state as a separate classification problem rather than a continuous modulation of user representation."*

3. > *"Lack of controllable intensity in mood-aware recommendations. Systems are binary: mood is either applied or not."*

**Our system addresses all three.**

### Novel Contributions

| # | Contribution | Status in Literature |
|---|-------------|---------------------|
| 1 | **Mood as a learned directional vector in the same semantic embedding space as content and users** | Not found in any published paper |
| 2 | **Controllable mood modulation via λ parameter (0.0 to 1.0)** | Explicitly listed as an open problem |
| 3 | **Mood directions empirically derived from data (mean difference), not hardcoded** | Existing systems use manual genre→mood mappings |
| 4 | **Geometry-based explanations referencing taste, mood, and specific similar movies** | Not possible in systems with separate models |

### What Already Exists (We're Not Claiming These)

To be academically honest, here's what prior work has done:

| Technique | Prior Work | How We're Different |
|-----------|-----------|-------------------|
| Semantic movie embeddings | Attidiya (2024 thesis), CineMood chatbot | They don't have mood-as-vector-shift |
| User embedding centroid | Multiple papers, standard technique | They don't modulate it with mood |
| Mood-based recommendation | Gao & Lin (PLoS One 2025), music mood papers | They use separate emotion models or 2D valence-arousal, not semantic space |
| Emotion-aware recommenders | ESE-DT (2025), multiple surveys | They classify emotion, don't use it as a geometric direction |

## Evaluation Strategy

### Dataset

**MovieLens 100K** (already in `data/raw/ratings.csv`):
- 100,000 ratings from 943 users on 1,682 movies
- Each user has ≥20 ratings
- Ratings on 1-5 scale

### Train/Test Split

For each user:
- **Train:** Earliest 80% of their ratings (chronologically)
- **Test:** Latest 20% of their ratings

Movies in the test set that the user rated ≥4 are "relevant." All others are "not relevant."

### Baselines

| Baseline | Description |
|----------|-------------|
| **B1: TF-IDF + Genre (Current System)** | Our current system. TF-IDF vectors, genre-based taste, hardcoded mood→genre mapping. |
| **B2: Static Centroid (No Mood)** | Semantic embeddings with user centroid. No mood shift (λ = 0). Measures the value of embeddings alone. |
| **B3: Genre-Filtered Mood** | Semantic embeddings + user centroid, but mood applied as a genre filter (like the current system's mood, but with embeddings). |
| **Ours: Mood-Shifted (λ = 0.3)** | Our proposed system with the default mood shift. |

### Metrics

| Metric | Formula | What It Measures |
|--------|---------|-----------------|
| **Hit Rate@K** | HR@K = (users with ≥1 relevant item in top K) / total users | Did we recommend at least one good movie? |
| **NDCG@K** | Normalized Discounted Cumulative Gain | How high are good movies ranked? (position-aware) |
| **Diversity@K** | 1 - (avg pairwise cosine similarity of top K) | How varied are the recommendations? |
| **Serendipity@K** | Fraction of relevant items not similar to user's most-watched genres | Did we find unexpected good matches? |

### Ablation Study

Sweep λ from 0.0 to 1.0 in steps of 0.1. Measure HR@10 and NDCG@10 at each point. Hypothesis: λ ≈ 0.3 achieves the best balance.

### Expected Results

```
Hypothesis table:

Baseline / Method         HR@10    NDCG@10   Diversity
─────────────────────────────────────────────────────
B1: TF-IDF + Genre        0.xx    0.xx       0.xx
B2: Static Centroid       0.yy    0.yy       0.yy    (higher: embeddings > TF-IDF)
B3: Genre-Filtered Mood   0.zz    0.zz       0.zz
Ours: λ = 0.3             0.ww    0.ww       0.ww    (highest: taste + mood synergy)
```

## Limitations and Future Work

### Limitations

1. **Mood exemplar selection is somewhat subjective.** We use keyword-based selection for mood exemplar movies. A larger-scale approach would use crowd-sourced mood labels.

2. **Single mood per query.** Users can only express one mood at a time. Real emotional states are complex blends (e.g., "excited but a little nostalgic"). Multi-mood blending is future work.

3. **No true collaborative signal.** We don't use the ratings matrix for collaborative filtering. Hybridizing our semantic approach with collaborative embeddings would likely improve results further.

4. **English-only.** The Sentence Transformer model is trained primarily on English text. Non-English movie descriptions would need a multilingual model.

5. **Static mood directions.** Mood directions are computed once and remain fixed. In reality, cultural associations between content and mood shift over time.

### Future Work

1. **Multi-mood blending:** Allow users to express "60% excited + 40% nostalgic" — the search position becomes a weighted blend of two mood directions.

2. **Learning λ per user:** Some users want strong mood influence; others want none. Learn the optimal λ from user behavior (do they like mood-shifted recommendations?).

3. **Hybrid collaborative + semantic:** Combine our semantic user centroid with a collaborative embedding from matrix factorization. Two-tower architecture: one tower for content, one for behavior.

4. **Temporal mood decay:** After selecting a mood, gradually decay λ back to 0 over time — simulating the natural fading of a transient emotional state.

5. **Cross-domain application:** Apply the same λ-shifted search framework to music, books, or podcast recommendations. The architecture is domain-agnostic.
